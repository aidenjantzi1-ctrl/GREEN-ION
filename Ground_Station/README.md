# GREEN ION V16.3 Windows Ground Station

**Run `START_GREEN_ION.cmd` from this folder.** `OPEN_GROUND_STATION.cmd` remains a compatibility alias. It starts the current dark-blue GREEN ION dashboard at `http://127.0.0.1:8765`, not the older V13 static page. The launcher checks Python 3.10+ and the pinned pyserial dependency. Plug the Uno in before or after startup; V16.2 keeps watching USB and can rediscover it after unplug/replug or a COM-port change. Use `START_GREEN_ION.cmd --port COM5` only when manual selection is needed. Run with motors removed for testing.

Windows may join the Feather `GREEN-ION-V16-3` access point while the command window remains open. The access point has no internet. The local server polls Feather `192.168.4.1` and Uno LoRa independently. Wi-Fi status is authoritative for SD recording state; when Wi-Fi is lost, received LoRa telemetry remains visible but **cannot command the rocket**.

All finished SD BIN files and available SEN/TXT companions are automatically imported from Feather after reconnecting. The current web app saves immutable originals in IndexedDB and mirrors them through `/api/local/save` to `%USERPROFILE%\GREEN_ION_Data\flights` using SHA-256. The Python server verifies the hash, bounds file sizes, refuses unsafe filenames and only binds to loopback; disk originals are never overwritten. The browser can restore them using `/api/local/files` and `/api/local/file`. Radio CSV stays in `%USERPROFILE%\GREEN_ION_Data\logs`.

The `/api/status` endpoint merges verified Feather Wi-Fi and receive-only LoRa with accurate age/source labels. V16 Phase 1 adds explicit **Connected / Delayed / Reconnecting / Disconnected** Wi-Fi states, last-success age, active-request diagnostics and failure counts. A stale Feather status can remain visible as last-known data, but it is never command-authorized. Other Feather `/api/*` calls are proxied to the fixed Feather IP only while freshly verified. Use `/api/v16/telemetry` for the fused source-aware mission feed; `/api/telemetry` and `/api/ground-link` remain lower-level diagnostics. Use `/config.js` for **publishable** browser settings only. Supabase uses a publishable key; optional embedded Google Maps uses `GOOGLE_MAPS_BROWSER_KEY` from the environment. No service-role/admin secret belongs in the browser.

When internet returns on the Windows computer, the open browser tab retries automatic Supabase backups **only if signed in and auto-sync enabled**. This server is not a background cloud uploader when the browser is closed. Keep the local tab open. Cloud never controls flight or OTA.

See [V16 Phase 2 unified telemetry](../docs/V16_PHASE2_UNIFIED_TELEMETRY.md), [V16 Phase 1 reliability details](../docs/V16_PHASE1_WINDOWS_RELIABILITY.md), [V16 implementation checklist](../docs/V16_IMPLEMENTATION_CHECKLIST.md), the [V15 workflow](../docs/V15_LOCAL_FIRST.md), and [hardware quality plan](../docs/V14_QUALITY_PLAN.md). Windows app updates use `UPDATE_GREEN_ION.cmd`; `ROLLBACK_GREEN_ION.cmd` returns to the previous complete app package without touching `GREEN_ION_Data`. Physical tests of RF range, LiPo, SD, iPhone networking and OTA remain required.
