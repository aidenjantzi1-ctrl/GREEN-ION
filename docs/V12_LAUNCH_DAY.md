# GREEN ION V12 launch-day data checklist

Use only after the physical validation record is complete for the equipment in use. GREEN ION measures, records and helps recovery; it does not control ignition, staging or parachute deployment. Follow the launch site and motor manufacturer's safety procedures independently.

1. Charge and inspect the LiPo. Power off before checking connectors, battery retention, SD seating, antennas, common ground and secure mounting in the selected rocket (Green Eggs, So Long or another compatible profile). Stop if wiring or power is uncertain.
2. Check SD free space and keep earlier raw flight files. Do not format or remove data to make room without a separate verified backup.
3. Start the Windows Ground Station with `OPEN_GROUND_STATION.cmd`. Confirm its page opens on the laptop. Connect laptop to Feather Wi-Fi; attach the Uno USB LoRa receiver only if its radio and antennas are actually installed and verified. Wi-Fi-only operation is valid.
4. In Settings, choose the observed Uno COM port if one is present. In Mission Control, confirm the real Feather firmware/version, Wi-Fi source, battery, SD and separate barometric/GPS altitude. A simulated page or stale packet is not readiness evidence.
5. Run **Full Preflight Test**. Read every PASS/WARNING/FAIL/NOT TESTED detail and resolve failed sensor, battery, SD or recorder checks. Verify outdoor GPS current fix and valid UTC where required for recovery; retain the last known coordinates separately from a confirmed landing point.
6. Keep the rocket stationary and use **Prepare Recorder** if calibration needs restarting. Confirm baseline/calibration, idle SD, and the automatic **Watch for Launch** state. Current V12 enables its watcher through preparation; there is no separate laptop switch to enable. Do not start a motor-free bench `TESTnnn.BIN` workflow as a substitute for a flight recording.
7. Before launch, confirm autonomous SD recording readiness on the Feather. The laptop and LoRa may disconnect during flight; onboard SD must continue independently. Do not use manual Stop/Save during ascent. Follow launch-site procedures for the actual rocket and motor.
8. During flight, monitor Mission Control's current/stale source labels, pressure-derived altitude, GPS altitude, motion, battery, recorder state and data-quality warnings. A missing telemetry packet is not proof that onboard logging stopped.
9. After landing, use Recovery's last valid rocket coordinate, fix age, phone/manual position, straight-line distance and true bearing. The last GPS fix is not guaranteed to be the touchdown point. Map imagery may fail; preserve coordinates and the offline track. Do not rely on walking directions from this application.
10. Reconnect to Feather Wi-Fi when possible. Inspect the SD recording list in Analysis, download the original BIN and matching SEN if present, and verify transfer length, RKT4/GIS1 integrity and SHA-256. Use Stop/Save only if a recording remains active after recovery and the operator has confirmed the exact file.
11. Import and analyze the original files, review graph gaps and warnings, add a rocket label/date only if known, and export the needed CSV/JSON/report. Create a laptop ZIP backup and keep a separate copy of the original SD files. Do not move the current laptop JSONL session to Trash.

If Preflight reports FAIL or required evidence stays NOT TESTED, pause the data mission and correct the cause. If links fail, rely on the rocket's independent SD recorder and recover using the last validated coordinate plus ordinary field procedures. If SD initialization or active writing fails, preserve the hardware state and logs for diagnosis; do not treat telemetry as a complete replacement for onboard recording.
