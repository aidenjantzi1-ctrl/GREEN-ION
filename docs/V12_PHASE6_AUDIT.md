# Phase 6 Analysis acceptance audit

This audit compares the supplied GREEN ION V12 eight-phase plan with the `codex/green-ion-v12` implementation. Software tests use generated fixtures and Chromium; no physical rocket, Feather SD card, Windows printer, or iPhone was exercised.

| Requirement | Software evidence | Remaining limit |
| --- | --- | --- |
| RKT4 v2 BIN, GIS1 SEN and JSONL | BIN importer validates the RKT4 layout and retains bytes; SEN pairing checks structure, CRC, flight sequence, rate and timestamp window; JSONL importer validates events and preserves bytes. | V11 and V12 physical flight files have not been supplied. V11 firmware source writes RKT4 v2, but archival binary files in the repository are firmware images, not flight recordings. |
| Flight library and SD access | Analysis lists imports with source, size, duration, label, profile, date, warning state and SHA-256. Feather SD list/download checks the reported length and imports the original BIN. | Physical SD download and SEN synchronization are NOT TESTED. |
| Synchronized analysis and summary | A bounded timeline matches SEN samples within half a sample period, reports missing/torn data, pressure-derived velocity, estimated barometric peak/time, GPS peak (altitude quality unverified)/last current fix, IMU magnitude and battery. | Legacy GIS1 stores position-current status without independent altitude freshness; its GPS peak may include an older altitude. The optional V12 reserved-byte marker excludes altitude explicitly reported noncurrent while older files remain quality unverified. Combined apogee is unavailable without validated GPS/barometer calibration. RKT4 lacks reliable launch and landing event timestamps, so these are not invented. Ground JSONL connection-loss events cannot safely be assigned to an onboard BIN without a shared flight identifier. |
| Graphs and replay | Fourteen series, full-flight or cursor-centered windows, cursor time/value, apogee marker, missing-value gaps, recorded-time play/pause/scrub and current-fix GPS trail. Display points are bounded for large recordings. | Downsampling can omit short sensor events; the raw files remain authoritative. Physical sensor accuracy is NOT TESTED. |
| Comparison and exports | Two to four onboard flights compare estimated barometric apogee, elapsed apogee time, GPS peak with altitude quality unverified, velocity, IMU magnitude, battery, last current fix, quality and sensor availability. CSV, JSON and printable HTML are available; PDF uses browser print/save. Full raw BIN/SEN downloads and BIN CSV/JSON exports now stream in bounded chunks after checksum validation. | Native PDF generation is not implemented. Browser print on the user's Windows computer is NOT TESTED. |
| Integrity, backup, management | Raw BIN/SEN SHA-256 is checked, duplicate import avoids rewriting originals, ZIP backup validates members and restores without overwriting. Laptop flight and completed-session Trash require a typed phrase and second confirmation, preserve recoverable bytes, and reject active-session or file conflicts. | Feather SD deletion is not exposed in V12. It must not be implied or automatically performed. A future explicit, guarded firmware workflow would need connected-hardware validation. |

The cloud-verifiable core of Phase 6 is implemented, but Phase 6 is **not fully accepted** until real V11/V12 BIN and SEN files, Feather SD transfer, Windows print/PDF and physical timing have been checked. Phase 7 secure iPhone networking has not begun. The next useful software task is to review the Phase 6 data and file-management limits against actual user recordings when available, then implement the Phase 7 secure local Companion server and authentication without exposing the existing laptop control API to an unauthenticated LAN client.
